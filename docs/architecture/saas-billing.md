# SaaS billing contract

Billing belongs to the SaaS control plane. Existing tenants retain access until
explicit subscription enrollment. Operators configure names, positive prices,
currencies and monthly/annual intervals; no default commercial prices are seeded.
Only active superusers with the existing OTP gate manage plans. Tenant HR model
permissions confer no billing administration rights.

## Plan catalog

Store integer minor units, accepting decimal input without rounding. Supported
Paystack currencies use two decimal places. Publishing is an explicit CSRF-protected
POST to Paystack's fixed API host, with server-side credentials and finite timeout.
Freeze commercial terms when publication begins. Archive plans instead of deleting
provider-linked records. A timeout or malformed response leaves publication uncertain:
never blindly repeat a POST that may already have succeeded. Reconcile against the
Paystack dashboard using the explicit verify-and-link action, which fetches an
existing plan and checks its terms and environment before linking it. No provider payloads or credentials
are logged. Local drafts can be edited without configuring a Paystack account.

## Payment verification requirements

Tenant-primary-admin checkout must use server-side pricing and trusted callback URLs.
Callbacks and signed webhooks must verify the provider transaction, exact price,
currency, customer and environment before idempotent activation. Duplicate events
must never extend service twice. Keep paid access through its paid-through date when
canceling renewal. Payment cannot override a manual suspension or deletion.
Subscription enrollment, payment ledger, in-app notices and trial expiry are implemented
in the billing slice. Feature enforcement remains separate. Catalog publication alone
does not enable billing for an existing tenant.

Provider reference: https://paystack.com/docs/api/plan

## Subscription implementation contract

Enrollment is explicit and platform-only. A subscription locks its plan; plan changes
and prorations are outside this slice. Existing tenants without enrollment stay on
the existing lifecycle. Trial access and paid access use explicit expiry timestamps.
Billing is accessible to active platform operators (with OTP) or the tenant's active
primary administrator. Support impersonation cannot authorize payment or auto-renewal.
The billing page stays reachable after expiry/suspension; deleted tenants cannot pay.

Checkout uses an unpredictable local reference and immutable price/email/environment
snapshots. The browser never supplies price or billing identity. Callback and webhook
verification share a transaction-locked payment ledger; a reference is credited once.
Webhook authentication uses constant-time HMAC-SHA512 on the raw bounded body before
JSON parsing. Unknown events/references are acknowledged without granting access.

Auto-renewal is opt-in. The first payment is one-time; only after verification may a
reusable authorization create a subscription starting at the paid-through date.
Persist a pending state before the external POST; uncertain creation is not retried
blindly. Failed setup does not undo paid access. A platform reconciliation action must
fetch and match the provider subscription before linking it. Cancellation preserves
paid time. Signed recurring invoices are bound to the known subscription/customer,
verified against the transaction API, and advance access to the invoiced period end,
rather than adding another month on every replay. No raw card/provider payload is stored.

In-app billing notices are scoped to that tenant's billing administrators. Expiry
notices can be generated by an explicit scheduled management command; access expiry
is enforced synchronously, without depending on the job. Feature entitlements are
not enabled by this billing slice.

## Operational limits

Plan switching and proration, re-enabling canceled recurring subscriptions, email/SMS
notices, feature entitlements and automated refund/dispute handling remain outside
this slice. Canceled subscriptions can renew manually. Once a provider customer is
bound, future checkout uses the last confirmed billing email; changing the tenant
primary administrator does not silently switch the payment customer.

An unresolved checkout can be closed by an operator after five minutes and an explicit
provider review with typed-reference confirmation. This revokes auto-renewal consent
on that checkout and permits a new attempt. It does not cancel the provider link; a
late verified payment still credits paid time once. Account deletion requires resolved
checkouts and stopped/reconciled renewal, so deletion cannot silently leave an active
provider subscription. Access enforcement remains independent of notification jobs.

Provider contracts: [transactions](https://paystack.com/docs/api/transaction/),
[subscriptions](https://paystack.com/docs/api/subscription/), and
[webhook signatures](https://paystack.com/docs/payments/webhooks/).
